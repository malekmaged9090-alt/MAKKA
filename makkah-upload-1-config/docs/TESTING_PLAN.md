## 3. اختبارات مطلوبة قبل الإنتاج

### RLS
- سائق أ: `select * from shipments` يجب ألا يعيد شحنات السائق ب.
- تاجر أ: `merchant_ledger` لا يعيد قيود التاجر ب.
- `authenticated` لا يستطيع `insert/update/delete` على `merchant_ledger` مباشرة.

### التزامن
```sql
-- 50 اتصالًا متوازيًا ينشئ شحنات
select next_shipment_serial('<company>');
-- تحقق: count(distinct serial_number) = 50
```

### E2E (Playwright)
1. تسجيل دخول الموزع → توزيع شحنة.
2. تسجيل دخول السائق → قبول → خروج → تسليم مع COD.
3. تسجيل دخول المحاسب → توريد → تسوية → اعتماد (مستخدم آخر) → دفع.
4. فتح `/track/{number}?t={token}` والتأكد من الحالة.

### الواجهة
- `npx tsc --noEmit` — نظيف.
- `npm run build` — 21 مسارًا، نجاح.
- فحص يدوي: RTL/LTR، طباعة 100×150 وA4، طباعة التسوية، PWA manifest.

## 4. فجوات معروفة
- لا اختبارات RLS آلية بعد (تحتاج Supabase محلي أو pgTAP).
- لا اختبار تزامن فعلي (الرقم التسلسلي مُختبر منطقيًا فقط عبر trigger وunique constraint).
- لا اختبارات متصفح آلية.
